# Как запустить «Кицунэ-календарь» по-настоящему

Сейчас сайт работает во временной песочнице — её адрес и данные **не постоянные**.
Ниже три рабочих пути. Рекомендую **Путь A**: бесплатно, ~15 минут, HTTPS, открывается
с любого телефона и браузера.

Что нужно сайту: **только база PostgreSQL**. Никаких платных API-ключей — распознавание
скриншотов (Tesseract.js) и чтение QR (jsQR) работают в браузере пользователя.

---

## Путь A. Vercel + Neon (бесплатно, без карты)

### 1. Залей код на GitHub
```bash
git init
git add -A
git commit -m "Кицунэ-календарь"
git branch -M main
# создай пустой репозиторий на github.com, затем:
git remote add origin https://github.com/<твой-логин>/kitsune-calendar.git
git push -u origin main
```

### 2. Бесплатная база: Neon
1. Зайди на <https://neon.tech> → **Sign up** (можно через GitHub).
2. **Create a project** → регион Frankfurt/London → **Create**.
3. Скопируй строку **connection string** (она вида
   `postgresql://user:pass@ep-xxxx.eu-central-1.aws.neon.tech/neondb?sslmode=require`).

### 3. Создай таблицы
Из папки проекта (локально), подставив свою строку:
```bash
DATABASE_URL="postgresql://...neon.tech/neondb?sslmode=require" npx drizzle-kit push
```
Либо вставь содержимое файла [`deploy/schema.sql`](deploy/schema.sql) в **SQL Editor**
в панели Neon и нажми Run.

> Проверить: `npx drizzle-kit pull` или в Neon посмотреть список таблиц — должны появиться
> `couples`, `users`, `sessions`, `partners`, `settings`, `uploads`, `day_classes`,
> `time_blocks`, `plans`.

### 4. Деплой на Vercel
1. <https://vercel.com> → **Sign up with GitHub**.
2. **Add New… → Project → Import** свой репозиторий.
3. Framework preset: **Next.js** (определится сам). Build/Output команды не трогай.
4. В разделе **Environment Variables** добавь:
   | Name | Value |
   |---|---|
   | `DATABASE_URL` | строка из Neon (шаг 2) |
5. **Deploy**. Через 1–2 минуты получишь адрес вида
   `https://kitsune-calendar.vercel.app` — это уже рабочая публичная ссылка с HTTPS.

### 5. Первый вход
1. Открой адрес → **Создать пару** → имя, логин, пароль, роль «я — он».
2. Откроется страница **Пара и QR** → покажи QR девушке.
3. Она сканирует его камерой телефона (или заходит на `/join` и прикрепляет
   скриншот QR **из галереи**, или вводит код `SAKURA-XXXXXX` руками) → регистрируется →
   попадает в ту же пару. Роль «она» выдастся автоматически.
4. Каждый загружает **два скрина**: пары и звонки/перемены. Анализ появится сразу.
5. На телефоне: меню браузера → **«На главный экран»** — будет работать как приложение
   (иконка с лисой уже настроена через манифест).

### 6. Свой домен (необязательно)
- **Бесплатно:** поддомен `is-a.dev` (заявка через GitHub), `eu.org`, `pp.ua`.
  В Vercel: **Settings → Domains → Add** → пропиши CNAME/A-запись у регистратора.
- **Платно:** `.ru` ≈ 200–300 ₽/год, `.com` ≈ 900–1200 ₽/год (reg.ru, timeweb, namecheap).
  После привязки Vercel сам выпустит сертификат.

### Особенности бесплатного тарифа
- Vercel Hobby разрешён для **некоммерческого** использования — для вас двоих идеально.
- Лимит тела запроса ~4.5 МБ: клиент сам сжимает скриншот до ~300 КБ, так что запас огромный.
- База «засыпает» после простоя: первый запрос может занять 2–4 секунды, дальше мгновенно.
- Neon Free: 0.5 ГБ — при 4 скриншотах в неделю это годы работы.

## Путь B. Свой VPS + Docker (полный контроль, ~250–500 ₽/мес)

Подойдёт, если хочешь «свой» сервер и независимость от бесплатных лимитов.

```bash
# на сервере (Ubuntu 22.04/24.04)
curl -fsSL https://get.docker.com | sh
git clone https://github.com/<твой-логин>/kitsune-calendar.git && cd kitsune-calendar

# домен/поддомен: A-запись на IP сервера, затем впиши его в Caddyfile
nano Caddyfile          # замени your-domain.example

# подними пароль БД
echo "POSTGRES_PASSWORD=$(openssl rand -hex 16)" > .env

docker compose up -d --build
docker compose exec -T db psql -U postgres -d app_db < deploy/schema.sql
```
Готово: Caddy сам получит и будет продлевать сертификат Let's Encrypt, сайт доступен
по `https://твой-домен`. Приложение смотрит только на `127.0.0.1:3000`, наружу торчит
лишь 80/443.

Обновление после правок: `git pull && docker compose up -d --build`.

## Путь C. Показать девушке сегодня же, без хостинга

Если нужно прямо сейчас продемонстрировать результат с её телефона:

```bash
# терминал 1 — база и сайт локально
npm install
# DATABASE_URL уже есть в .env
npx drizzle-kit push
npm run build && npm run start     # или npm run dev

# терминал 2 — публичный туннель
npx cloudflared tunnel --url http://localhost:3000
# либо: ngrok http 3000
```
Туннель выдаст ссылку `https://<случайное-имя>.trycloudflare.com` — её можно открыть
с любого устройства, QR-код пары будет вести на этот же адрес. Ссылка живёт, пока
включён твой компьютер, поэтому для постоянного использования переходи на Путь A или B.

## Чек-лист после запуска

1. Зарегистрировались оба, страница **Пара и QR** показывает «Пара соединена».
2. В **Настройках** проверь: дорогу до её техникума (по умолчанию 30 мин), её
   комендантский час, допустимый разрыв (1 пара) и лимит ожидания (50 мин).
3. Загрузили по 2 скрина → на вкладке **Расписание** сверили распознанные пары и перемены.
4. Открыли **Обзор недели** → выбрали лучший день → кнопка «В план».
5. **Раз в неделю** заменяйте скриншоты (кнопка «Заменить»): сами они не обновляются,
   а через 7 дней появится напоминание «N дн. назад».

## Бэкап и перенос данных

```bash
# Vercel + Neon: дамп всей базы
pg_dump "$DATABASE_URL" > backup.sql
psql "$NEW_DATABASE_URL" < backup.sql

# VPS: снапшот базы из docker
docker compose exec -T db pg_dump -U postgres app_db > backup.sql
```
В базе лежат и аккаунты, и скриншоты — перенос на другой хостинг сводится к переносу
строки `DATABASE_URL` и этого дампа.

## Безопасность

- Пароли хранятся как `scrypt`-хеш с индивидуальной солью, сессии — в таблице `sessions`
  (httpOnly-cookie, 60 дней, `Secure` в production — поэтому нужен HTTPS).
- Каждая пара видит только свои данные: все запросы фильтруются по `coupleId`.
- Скриншоты отдаются только авторизованным участникам пары.
